# Alpha 1.0.3 distribution candidate — mod 0.18.30

Prepared locally on 2026-10-17. Target: **Windows 64-bit, Mindustry 160.7**.
Nothing is pushed, published, uploaded or subscribed by these tools. Historical
Alpha files/checkpoints are preserved. See the final package's manifest for its
source checkpoint, SHA-256 hashes and canonical multiplayer payload identity.

## Runtime independence audit

Audited all `src/main/java`, generated configuration, resources and build tools.
Ordinary runtime code contains no developer-drive file paths and does not open
assets from the source tree. Original sprites, atlas pixels, sounds, Arc/SDL,
networking and native game types come from the installed host. Procedural model
geometry and render shaders are generated in the mod. The JAR contains all 830
FPV classes (Java class version 61), 152 JNA classes/native resources, 22 design
sheets, metadata, GPL and dependency notices. Total: 1010 entries.

Required from the player/system:

- A separately installed, owned Mindustry 160.7 desktop host and its normal Steam
  client/runtime; its bundled Java 25.0.1 suffices. The inspected runtime provides
  `java.base` and `jdk.unsupported` but not `java.logging`.
- Windows 64-bit, working OpenGL graphics drivers, and writable game profile/temp
  directories. Windows supplies `user32.dll`/`kernel32.dll`; the game supplies
  SDL/audio/Steam libraries. None is copied into player downloads.
- No separately installed Java/JDK, Python, PowerShell, source tree, game profile,
  controller, Liftoff installation or developer utility is required to play.

Bundled: unmodified JNA core 5.19.1 Java/native payload, including Win64 dispatch,
GPL-3.0-only, JNA Apache-2.0 and libffi notices. Full Java 17 uses JNA; stock Java
25 uses the java.base FFM binding and the host launcher's existing native-access
permission. Native input failure still leaves the bounded HOST MOUSE fallback.
This remains recentered cursor input, not raw HID input.

Old developer launchers/profilers do contain absolute paths and dependencies on
JDKs, recordings and fixtures. They are historical opt-in diagnostics, excluded
from the player ZIP and Workshop folder. Design descriptors preserve historical
provenance strings; they are not file-loading instructions. Modern `build.py`
uses explicit build dependencies and refuses to overwrite a versioned JAR.

Isolated profile tests are **on the development PC**, not a clean machine.
Restart class-loading logs show FPV classes coming only from the installed JAR
or extracted folder; the parent classpath contains the installed host JAR only.
The native import instrument is removed from the restart classpath. Steam's
existing subscribed maps can be enumerated by the host, but fixtures generate
their own maps and require none of those files. Independent Windows/PC testing
is still required before claiming clean-machine acceptance.

## Packaging and compatibility fix

The old `FpvNetwork.jarFingerprint()` required a regular JAR file and threw while
initializing an extracted Workshop directory. `ModFingerprint` now hashes sorted
relative payload paths, lengths and bytes identically for archives and folders.
ZIP order, timestamps and compression are excluded. Only root `steamid.json`,
`preview.png` and `icon.png` are cosmetic; compiled code, metadata/version,
resources, design sheets, dependencies and notices all participate.

Invalid paths, duplicate archive paths, links, incomplete payloads and I/O errors
produce unavailable verification rather than aborting single-player startup.
Unverified peers cannot authenticate, and unverified network startup is closed.
Verified peers still require an exact matching token and protocol. This is
compatibility verification, not cryptographic client authentication/anti-cheat.
Older 0.18.29 peers deliberately do not match this new build.

One canonical payload is used for:

- `mindustry-fpv-0.18.30.jar`: direct native Import File installation.
- `mindustry-fpv-0.18.30-windows.zip`: that same JAR, licenses and `INSTALL.txt`.
  Extract first; the convenience ZIP itself is not an importable mod.
- `workshop/Mindustry3/`: compiled classes/resources directly beneath root
  `mod.hjson`, plus an original generated `preview.png` required by the native
  publisher. The matching Workshop ZIP is for the future uploader, not Import.

The preview is original project artwork generated by `tools/workshop_preview.py`;
no game artwork or proprietary runtime is bundled. The source ZIP is exported
from the exact public Git checkpoint and includes a per-file source manifest.

## Mod Browser readiness and remaining release-selection blocker

As of 2026-10-17 the public repository's topics do **not** include `mindustry-mod`.
Prepared root and packaged `mod.hjson` are byte-identical: 0.18.30, Java entrypoint,
minimum 160.7, `hidden: false` and **`hideBrowser: true`**. No remote topic or
visibility is changed. The browser opt-out is deliberate pending release approval.

[Upstream browser criteria](https://github.com/Anuken/MindustryMods#criteria)
require root/assets metadata and the discovery topic. For a future approved
pre-release, recommend release title **`Mindustry³ Alpha 1.0.3 [v160.7]`**.
The current upstream indexer includes non-draft pre-releases in version-specific
release maps, and the actual 160.7 host parser selects the indexed release ID.
Keep exactly one player `.jar` asset; the host prioritizes a `dexed*.jar` asset
if present, so do not publish an unrelated/developer JAR beside the mod.

Direct GitHub-repository import without an indexed matching release requests
`/releases/latest`. [GitHub excludes pre-releases from that endpoint](https://docs.github.com/en/rest/releases/releases#get-the-latest-release).
All three currently published Alphas are pre-releases, so this fallback does
not select them. Explicit release selection or a future indexed `[v160.7]`
release is needed; pre-release status alone is not an installation guarantee.
No actual browser download of the unpublished candidate is claimed tested.

After approval, synchronize any metadata/discovery change with its rebuilt JAR
and source checkpoint. Never silently change metadata under an already released
version/fingerprint. Do not add the discovery topic or remove the opt-out here.
