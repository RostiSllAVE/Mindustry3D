# A2-16d — Owner checks

Import `mindustry-fpv-a2-16d-diagnostics.jar` through Mindustry 160.7
**Mods → Import Mod**, restart, and enable only one copy. No developer directory
or separate Java installation is required. The same JAR is for the existing
Windows/Linux desktop paths; physical Linux acceptance remains pending. Windows
fullscreen is recommended because of the previously observed windowed issue.
Use a disposable map/save or a backup. No new controls are added.

1. **Six machines, real production and stopping.** Place Graphite Press,
   Multi-Press, Silicon Smelter, Silicon Crucible, Pyratite Mixer and Blast Mixer
   beside working belts. Supply their normal inputs/power/liquids. In F5 FPV and
   Tab Build Mode, look from above and close to the side. Check single/twin press
   strokes, attached rods, mixer paddles and furnace heat. Remove input or power,
   disable a block, and let an output fill: machinery should rest/coast/cool
   appropriately; resume supplies and confirm normal resource output. Inspect
   neighboring conveyor items and ports for obstruction or clipping.

2. **Upper floors and copying.** Use supported platforms or explicitly
   host-enabled Free Mode. Place all six on Z1 and on higher floors. For a
   same-X/Y stack use Z1/Z3/Z5: the factory's physical height legitimately prevents
   placing the next slab immediately above it. Look from the side and below,
   checking that each base sits on its own platform and opaque slabs hide lower
   machinery. Copy/paste a valid multi-floor group with the existing volume tool;
   check full build completion, selection outlines and partially built ghosts.

3. **Dense layout and reload.** Inspect a field of operating factories while
   moving between low-angle FPV and high Build Mode views. Save/reload and, if
   convenient, change a disposable campaign sector. Confirm models, progress,
   resources and links remain correct. Check F3 stop/resume, Alt-click blueprint
   priority, F5, Tab, menus and mouse release/capture. Repeat on the Linux laptop
   when available. For multiplayer, both peers need the identical diagnostic JAR;
   a real two-computer check is still required for acceptance.

Report the block, floor, operating state, viewing angle and a screenshot if an
artifact appears. Scripted OpenGL screenshots and automated native tests are
included as evidence; they do not substitute for these physical checks.
